# M12 `desktop-ui` (Qt6/QML, Plasma 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the native C++20 + Qt6/QML desktop thin client (`binance-bot-ui`) with optional KF6 Plasma 6 integration, UDS protocol v1 `klines`/`trades` support, view-only lock, 1.5s hold-to-confirm nonce flow, 9 screens, and automated CTest smoke/integration suites.

**Architecture:** Extend `bot-ipc` protocol v1 in lockstep (schema + Rust UDS/WS/HTTP + `web-ui` types) with typed `get_klines`/`klines` and `get_trades`/`trades` envelopes carrying `venue`. Build `desktop-ui` as a static core library (`binance-bot-ui-core`) + QML module (`URI BinanceBot`, `RESOURCE_PREFIX /qt/qml`) + executable (`binance-bot-ui`), using `QtQuick.Controls`/`Canvas` across all 9 pages so a single QML codebase runs cleanly on both Qt 6.4 (Ubuntu 24.04 CI) and Qt 6.12 + KF6 (CachyOS Plasma 6), while isolating `KF6StatusNotifierItem`/`KF6Notifications` behind `#ifdef HAVE_KF6` in `Notifier`.

**Tech Stack:** Rust (`bot-ipc`, `serde`, `tokio`), JSON Schema 2020-12, TypeScript (`web-ui` contract mirror), C++20, CMake ≥ 3.22, Ninja, Qt 6 (`Core`, `Gui`, `Widgets`, `Qml`, `Quick`, `QuickControls2`, `Network`, `Test`), optional KDE Frameworks 6 (`StatusNotifierItem`, `Notifications`, `I18n`).

**Spec:** `docs/superpowers/specs/2026-11-23-m12-desktop-ui-design.md` (and `docs/milestones/M12-desktop-ui.md`, `docs/spec/11-ui.md` §11.1–11.4, `docs/spec/10-ipc.md`, `docs/spec/12-deployment.md` §12.2).

## Global Constraints

- Default mode is always `paper`; zero trading logic or indicator calculations in UI; zero hardcoded domain numbers in QML (`StateStore` is single source of truth).
- Rust code: `#![forbid(unsafe_code)]`, zero `unwrap`/`expect`/`panic`/indexing in non-test code, `clippy --workspace --all-targets -- -D warnings`.
- Every IPC table/record/query carries `venue` (`"spot"` | `"futures"`).
- All prices, quantities, balances, PnL, R-multiples, and risk limits remain exact decimal strings (`DecimalString` / `QString`); conversion to `double` is allowed strictly inside `CandlesChart.qml` pixel math and `RiskGauge.qml` bar-ratio math.
- Baseline compatibility: Qt 6.4.2 (Ubuntu 24.04) through Qt 6.12+ (CachyOS). Never call Qt 6.5+ only APIs (`loadFromModule`, `QTP0001`); load `qrc:/qt/qml/BinanceBot/qml/Main.qml` under `QApplication` (`Qt6::Widgets`).
- Destructive commands (`panic_flatten`, `reset_kill`): require 1.5s continuous hold (`HoldToConfirmButton`) + 10s server `confirm_nonce` (`QUuid::WithoutBraces`); no single-key shortcut; no `PANIC` in system tray menu.
- Controls start locked (`controlsUnlocked == false`) until operator clicks `Unlock Controls`.
- Implicit socket discovery checks only `/run/binance-bot/bot.sock` and `$XDG_RUNTIME_DIR/binance-bot/bot.sock` (never `/tmp` unless explicitly passed via `--socket` or `BINANCE_BOT_SOCKET`), plus Linux `SO_PEERCRED` peer UID/GID verification.

## Review Focus

1. **UUID formatting over UDS (`QUuid::WithoutBraces`):** Qt's default `QUuid::toString()` wraps braces `{...}`, which fails `ipc-v1.schema.json` and causes `uds.rs` to drop the client connection immediately — pinned by `tst_ipc_uds_integration::commandAndConfirmNonceFlowAgainstRustUds`.
2. **Interleaved telemetry frames during `request_confirm` → `panic_flatten`:** Heartbeat or delta frames arriving between `request_confirm` and its `command_result` must not confuse pending command resolution or trigger spurious `seq` gap loops — pinned by `tst_ipc_uds_integration::interleavedTelemetryDuringConfirmFlow`.
3. **Spoofed or unauthorized peer UDS socket:** Connecting to a socket owned by an untrusted UID (when testing peer check) or implicit `/tmp` path must be rejected before trusting `hello`/`snapshot` — pinned by `tst_ipc_uds_integration::socketDiscoveryNeverUsesImplicitTmpAndChecksPeerCred`.
4. **Reconnect alert storm:** Re-receiving an unacknowledged `AlertView` with the same `id` on reconnect/snapshot refresh must not fire duplicate desktop notifications — pinned by `tst_decimal_and_store::deduplicatesAlertNotificationsAcrossSnapshots`.
5. **Headless / offscreen QML warnings & missing D-Bus:** Running `binance-bot-ui` or `tst_qml_smoke` under `QT_QPA_PLATFORM=offscreen` without a D-Bus tray must produce zero Qt/QML warnings and clean exit — pinned by `tst_qml_smoke::loadsMainWindowAndRendersSnapshotWithZeroWarnings`.
